# 工艺流程图编辑器模块设计方案

## 1. 概述

本文档旨在详细阐述工艺流程图（Process Flow Diagram, PFD）编辑器模块的设计与实现方案。该模块是数据库应用平台的核心功能之一，允许用户通过拖拽的方式绘制工业生产流程图，将图元（如设备、仪表）与数据库中的实时数据点进行绑定，并动态展示生产过程中的实时数据。

## 2. 功能需求

### 2.1 核心功能

- **画布绘制**：提供一个无限或可配置大小的画布，支持拖拽、缩放、平移等基本操作。
- **图元库**：提供一个包含常用工业设备（如泵、阀门、罐体、仪表）图元的组件面板，支持将图元拖拽至画布中生成节点。
- **连接线**：支持在不同图元的连接点之间绘制连接线（边），以表示物料或信号的流向。
- **属性编辑**：选中画布中的图元或连接线时，可在属性面板中查看和编辑其属性（如名称、ID、样式等）。
- **数据绑定**：支持将画布中的图元与一个或多个数据库中的实时数据测点（Tag）进行关联。
- **实时数据展示**：图元能够根据绑定的数据点实时更新其状态、颜色或显示的数值。
- **保存与加载**：支持将绘制的流程图保存到数据库，并能从数据库加载已有的流程图进行编辑或查看。

### 2.2 模式区分

- **编辑模式 (Editor Mode)**：提供完整的编辑功能，包括图元的增删改、连线、属性编辑和数据绑定。
- **浏览模式 (Viewer Mode)**：只读模式，隐藏编辑控件，仅用于展示流程图和实时数据，通常用于大屏监控或日常巡检。

## 3. 技术选型

- **前端框架**：React + Vite
- **绘图库**：**React Flow** - 一个功能强大且高度可定制的 React 流程图库，提供了节点、边、拖拽、缩放等核心功能，社区活跃，生态完善。
- **状态管理**：Zustand 或 React Context - 用于管理编辑器状态和全局配置。
- **后端框架**：Go + Gin
- **数据库**：PostgreSQL (用于存储流程图的结构化数据)
- **实时通信**：WebSocket - 用于后端向前端推送实时数据更新。

## 4. 模块设计

### 4.1 前端架构

前端编辑器主要由以下几个核心组件构成：

1.  **`DiagramCanvas` (画布组件)**
    - 基于 `ReactFlow` 组件构建。
    - 负责渲染节点（图元）和边（连接线）。
    - 管理画布的视口状态（缩放、平移）。
    - 处理用户的交互事件，如节点拖拽、点击、连线等。

2.  **`Toolbar` (工具栏)**
    - 提供常用操作按钮，如保存、撤销、重做、放大、缩小、适应画布等。
    - 提供编辑/浏览模式的切换开关。

3.  **`ComponentPalette` (图元组件面板)**
    - 以侧边栏形式展示所有可用的图元。
    - 实现图元的拖拽功能（Drag and Drop），将图元从面板拖拽到画布上创建新节点。

4.  **`PropertiesInspector` (属性检查器)**
    - 以侧边栏形式展示。
    - 当用户在画布上选中一个节点或边时，此面板会显示其详细信息。
    - 提供表单控件，允许用户修改选中元素的属性，如名称、标签、颜色等。
    - **核心功能**：提供数据绑定界面，允许用户搜索并选择要关联的数据测点。

### 4.2 后端架构

1.  **数据库模型**
    - 在 PostgreSQL 中创建 `process_flow_diagrams` 表，用于存储流程图。
    - 核心字段：
        - `id` (UUID, Primary Key): 唯一标识符。
        - `name` (VARCHAR): 流程图名称。
        - `content` (JSONB): **核心字段**，用于存储 `React Flow` 生成的节点、边和视口（viewport）的完整数据结构。JSONB 格式便于未来进行索引和查询。
        - `project_id` (UUID, Foreign Key): 关联到项目或资产（如果需要）。
        - `created_at`, `updated_at`, `created_by`, `updated_by`: 标准审计字段。

2.  **API 接口设计**
    - 使用 RESTful 风格设计 API。
    - **`Diagrams API (/api/v1/diagrams)`**:
        - `POST /`: 创建一个新的空白流程图。
        - `GET /`: 获取所有流程图的列表（不含 `content`，仅含 `id` 和 `name`）。
        - `GET /:id`: 获取指定 ID 的流程图的完整信息（包含 `content`）。
        - `PUT /:id`: 更新指定 ID 的流程图（主要用于保存 `content`）。
        - `DELETE /:id`: 删除指定 ID 的流程图。

3.  **WebSocket 服务**
    - **端点**: `/ws/diagrams/:id/data`
    - **工作流程**:
        1.  前端在加载一张图后，根据图 ID 建立 WebSocket 连接。
        2.  连接建立后，前端将当前图上所有需要订阅的数据测点 ID 列表发送给后端。
        3.  后端收到测点列表后，启动一个或多个 Goroutine，从 TDengine 或其他数据源订阅这些测点的实时数据。
        4.  当后端获取到任何一个测点的新数据时，立即通过 WebSocket 将 `{"tag_id": "xxx", "value": 123.45, "timestamp": "..."}` 格式的数据推送给前端。
        5.  前端 WebSocket 客户端接收到数据后，更新对应的节点状态。
        6.  当连接断开时，后端停止相应的数据订阅，释放资源。

## 5. 实施步骤

详细的实施路线图请参考与 Cline 的对话记录。总结如下：

1.  **阶段一：后端基础建设**
    - 创建数据库表。
    - 定义 Go 数据模型。
    - 实现后端的 CRUD API 接口。

2.  **阶段二：前端编辑器骨架搭建**
    - 安装 `reactflow` 依赖。
    - 创建 `DiagramEditor` 核心组件，实现基础的画布功能。
    - 创建路由页面并集成编辑器。

3.  **阶段三：前后端集成 - 保存与加载**
    - 在前端实现 API 调用逻辑。
    - 添加保存和加载功能，实现流程图的持久化。

4.  **阶段四：实现实时数据展示**
    - 在后端搭建 WebSocket 服务。
    - 在前端实现 WebSocket 客户端，并根据推送的数据更新节点状态。

5.  **阶段五：功能完善与体验优化**
    - 开发图元组件面板。
    - 开发属性检查器和数据绑定 UI。
    - 增加撤销/重做、对齐线、网格背景等高级功能。
