# ProDB 架构与功能完善计划

## 目标
- 明确系统边界与数据流，统一认证与配置治理，提升可观测性与可靠性
- 完善前后端功能闭环（采集器—平台—TDengine—可视化—查询导出）

## 架构治理
- OpenAPI 契约：为 `/api/v1` 生成规范并作为单一事实源，前端用 Typed Client
- 统一认证：移除后端演示 Mock，采用 JWT/签名校验；采集器使用密钥轮换与时效
- 配置中心：提炼配置模板/版本/发版的领域模型与状态机，加入审计轨迹
- 可观测性：标准化结构化日志、指标、分布式追踪；统一错误分类与兜底

## 采集器与同步
- 协议框架：抽象协议驱动接口，统一生命周期与重试/退避策略
- 缓存与同步：SQLite 写入幂等键，批量上传接口，断网回放与限速
- 健康监控：心跳扩展为状态机（启动→运行→退避→降级→故障）

## 平台后端（TDengine）
- 适配层：将 TDengine 逻辑封装为 Service/Repository，隔离 SQL 构造
- 查询模板与分页：新增查询构建器、分页兜底、限流与慢查询记录
- 导出服务：增量与全量导出任务，状态跟踪与失败重试

## 前端平台
- 鉴权与路由：统一守卫与刷新逻辑，错误页与会话过期处理
- 仪表盘：指标对齐后端 Prom/TDengine，增加阈值、趋势与告警联动
- 数据库管理：库/超表/子表增删查改与校验流程完善；表格与大数据集虚拟化
- 查询构建器：结构化查询组件 + 保存/分享模板 + 导出
- 测试：路由/Store/API 的集成测试和 MSW Mock 场景

## 运维与交付
- 容器化与部署：健康检查、就绪探针、资源与节点亲和；环境变量规范
- CI：多模块流水线、测试覆盖率阈值、合规扫描（lint/knip）
- 文档：自动从 OpenAPI 与代码注释生成 API/开发手册

## 交付顺序（Phase）
1. 契约与认证：OpenAPI → Typed Client → 统一认证与错误模型
2. 采集与同步：协议抽象、幂等批量上传、断网回放与指标
3. 功能完善：查询构建器、数据库管理全流程、导出服务

如确认采用，我将按以上 Phase 逐步实施并在每阶段提供可验证的交付成果。
